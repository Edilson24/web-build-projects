# Detalhes Técnicos

## 1. Ambiente de Desenvolvimento

O projeto será desenvolvido utilizando PHP como tecnologia principal para o backend e processamento das requisições, complementado por **HTML, CSS e JavaScript** para a construção e interação da interface web.

A aplicação será estruturada seguindo o padrão arquitetural **MVC (Model-View-Controller)**, conforme definido nos requisitos do projeto. Essa organização permitirá separar as regras de negócio, o acesso aos dados e a apresentação da interface, facilitando a manutenção e evolução do sistema.

O ambiente de desenvolvimento será configurado sem a utilização do XAMPP. Em seu lugar, será utilizado o **servidor HTTP embutido do próprio PHP**, através do comando `php -S`, eliminando a necessidade de instalação e configuração de um servidor Apache separado.

### Tecnologias principais

* **PHP 8.x** — processamento da aplicação e backend;
* **HTML5** — estrutura das páginas;
* **CSS3** — estilização e apresentação;
* **JavaScript** — interações e comportamentos no frontend;
* **MySQL** — sistema de gestão da base de dados;
* **PDO** — comunicação segura entre PHP e MySQL;
* **Git/GitHub** — controle de versões, quando aplicável;
* **Navegador Web** — execução e teste da aplicação.

O MySQL Server será executado localmente através da porta padrão **3306**. O MySQL Workbench será utilizado como ferramenta de administração e desenvolvimento da base de dados.

---

## 2. Servidor Web

A aplicação não dependerá do XAMPP nem do Apache para execução durante o desenvolvimento.

Será utilizado o **PHP Built-in Web Server**, disponibilizado nativamente pelo PHP:


php -S localhost:PORTA


O servidor disponibilizará os arquivos da aplicação através de uma porta HTTP local.

A porta não será necessariamente fixa. Para evitar conflitos com outros serviços em execução na máquina, será implementado um mecanismo de procura automática por uma porta disponível.

Por exemplo:


8000 → ocupada
8001 → ocupada
8002 → disponível


Nesse caso, a aplicação será disponibilizada em:


http://localhost:8002


Essa abordagem permite executar o projeto sem depender de uma configuração manual do Apache ou da porta 80.

---

## 3. Gerenciamento do Servidor

Será criada uma classe responsável pelo gerenciamento do processo do servidor PHP, denominada conceitualmente **`PhpServerManager`**.

Essa classe não implementará um servidor HTTP próprio. Sua função será apenas controlar o servidor disponibilizado nativamente pelo PHP.

Entre suas responsabilidades estarão:

* verificar a disponibilidade do PHP;
* procurar uma porta livre;
* iniciar o PHP Built-in Server;
* armazenar informações do processo iniciado;
* verificar se o servidor está em execução;
* disponibilizar a URL atual da aplicação;
* reiniciar o servidor quando necessário;
* encerrar corretamente o processo do servidor.

O fluxo de inicialização será semelhante a:

Executar projeto
      ↓
Verificar PHP
      ↓
Procurar porta disponível
      ↓
Iniciar PHP Built-in Server
      ↓
Confirmar que o servidor está disponível
      ↓
Construir URL
      ↓
Exibir URL no console
      ↓
Abrir navegador automaticamente
```

Ao encerrar a execução, o processo do servidor deverá ser finalizado de forma controlada, evitando que processos PHP permaneçam executando desnecessariamente.

---

## 4. Abertura Automática da Aplicação

Depois que o servidor estiver efetivamente disponível, o sistema poderá abrir automaticamente o navegador padrão do computador.

A URL será construída dinamicamente a partir do host e da porta selecionada.

Por exemplo:


http://localhost:8002/login
```

A porta não será codificada diretamente nas páginas ou controladores da aplicação.

Dessa forma, caso o servidor seja iniciado em outra porta, a aplicação continuará funcionando sem necessidade de alteração manual das URLs.

Caso a abertura automática do navegador não seja possível, a URL será apresentada no console para acesso manual.

## 6. Base de Dados

O sistema utilizará **MySQL Server** como sistema de gestão da base de dados.

A conexão será realizada localmente através de:


Host: localhost
Porta: 3306
```

O acesso à base de dados será realizado pelo PHP utilizando **PDO** e consultas preparadas (*prepared statements*).

A configuração da conexão será mantida separada da lógica da aplicação, permitindo centralizar os parâmetros necessários para acesso ao banco.

O projeto também incluirá um script SQL responsável pela criação da base de dados e das respectivas tabelas, conforme exigido nos entregáveis.

O **MySQL Workbench** será utilizado como ferramenta de apoio para criação, consulta e administração da base de dados, não sendo responsável por executar a aplicação PHP.

---

## 7. Separação entre Servidor Web e Banco de Dados

O servidor HTTP e o servidor MySQL serão tratados como serviços independentes.

A arquitetura será:


                 Navegador
                     │
                     ▼
             PHP Built-in Server
               localhost:8xxx
                     │
                     ▼
              Aplicação PHP
                     │
                     │ PDO
                     ▼
                MySQL Server
               localhost:3306
```

A classe responsável pelo servidor PHP não terá responsabilidade sobre a conexão com o MySQL.

Da mesma forma, a camada de acesso à base de dados não será responsável pelo gerenciamento do servidor HTTP.

Essa separação permitirá manter responsabilidades técnicas bem definidas.

---

## 8. Segurança

A aplicação deverá implementar as medidas de segurança previstas nos requisitos do projeto.

Os dados recebidos através de requisições `GET` e `POST` deverão ser validados e filtrados.

Para proteção contra **XSS (Cross-Site Scripting)**, será utilizada a função:

```php
htmlspecialchars()
```

Para proteção contra **SQL Injection**, o acesso à base de dados será realizado através de **PDO com prepared statements**.

As senhas dos utilizadores não serão armazenadas em texto simples. Será utilizada:

```php
password_hash()
```

para armazenamento e:

```php
password_verify()
```

para validação das credenciais.

Os ficheiros enviados através do sistema também deverão passar por validações de tipo e tamanho antes de serem armazenados.

Esses mecanismos correspondem aos requisitos de segurança definidos no enunciado do projeto.

---

## 9. Gestão de Sessões e Cookies

O sistema utilizará sessões PHP para manter o estado de autenticação dos utilizadores.

O processo de autenticação deverá contemplar:

* criação da sessão após login válido;
* proteção das páginas que exigem autenticação;
* encerramento da sessão no logout;
* utilização de cookies para a funcionalidade "Lembrar-me";
* validade do cookie de lembrança de sete dias.

Esses mecanismos fazem parte dos requisitos funcionais de autenticação definidos pelo docente.

---

## 10. Upload de Ficheiros

O sistema permitirá o carregamento de fotografias de perfil.

Os ficheiros serão armazenados no servidor, dentro de um diretório específico da aplicação.

Antes do armazenamento, serão realizadas verificações relacionadas ao:

* tipo do ficheiro;
* tamanho do ficheiro;
* possíveis erros durante o upload;
* nome e localização do ficheiro.

As operações de upload deverão utilizar tratamento adequado de exceções, conforme estabelecido nos requisitos do projeto.

---

## 11. Gestão de Erros e Logs

A aplicação deverá utilizar mecanismos de tratamento de erros e exceções para evitar que falhas internas sejam apresentadas diretamente ao utilizador.

As operações críticas, principalmente relacionadas à base de dados e upload de ficheiros, deverão utilizar `try-catch` quando aplicável.

O sistema deverá possuir um ficheiro:


logs/error.log
```

destinado ao registo de erros para fins de diagnóstico e depuração.

Ao utilizador deverão ser apresentadas mensagens amigáveis, evitando expor informações técnicas ou sensíveis da aplicação.

Esse comportamento está diretamente relacionado aos requisitos de gestão de erros e exceções definidos no documento do projeto.

---

## 12. Configuração Inicial do Ambiente

Para executar o projeto, o computador deverá possuir:

1. PHP instalado e disponível no `PATH`;
2. MySQL Server instalado e em execução;
3. MySQL Workbench, caso seja necessário administrar visualmente a base de dados;
4. navegador web;
5. código-fonte do projeto;
6. base de dados criada através do script SQL fornecido.

O projeto não dependerá da instalação do XAMPP.

Após a configuração do banco de dados, o servidor poderá ser iniciado através do mecanismo de inicialização definido pelo projeto.

## 15. Considerações Técnicas

A utilização do PHP Built-in Server tem como objetivo simplificar o ambiente de desenvolvimento e eliminar dependências desnecessárias, mantendo o foco nas funcionalidades exigidas pelo projeto.

O servidor embutido será utilizado como mecanismo de execução local da aplicação, enquanto o MySQL Server permanecerá responsável exclusivamente pelo armazenamento e gerenciamento dos dados.

A solução, portanto, será composta principalmente por:


PHP
  │
  ├── PHP Built-in Server
  ├── MVC
  ├── Sessões e Cookies
  ├── Autenticação
  ├── CRUD
  ├── Upload
  ├── Validação
  ├── Segurança
  ├── Gestão de erros
  └── Email
          │
          ▼
        PDO
          │
          ▼
       MySQL
    localhost:3306
```

Essa configuração permite manter o ambiente simples, organizado e independente do XAMPP, sem alterar os requisitos funcionais e técnicos estabelecidos para o desenvolvimento do sistema.
